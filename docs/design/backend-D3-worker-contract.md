# D3 多 Worker 验收与最小运行观察契约

2026-10-30。承接 D2，用户批准本批只做多 Worker 并发验收与最小关联日志。迁移保持 `0011_dispatch_intent`。本文件描述实现边界；实际结果以 D3 性能报告和验证清单为准。

## 范围和执行保护

分别测量 Outbox 投递和查单恢复的 1／2／4 个真实 Worker 进程，不将两类吞吐混合。保持原 CLI 循环、每轮 0.5 秒等待、有界 HTTP 尝试及所有数据库领取、发送许可、完成和恢复逻辑。

不修改领域状态机、库存不变量、员工/session 权限、可信确认、原回执、内部 snapshot 行锁/run_guard、仓储协议、Inbox/UNKNOWN 规则或有限预算。不新增基础设施、迁移、索引、依赖、模型调用或业务功能。CI/Docker 是后续批次。

所有数据库验证只允许 `127.0.0.1:55434/aftercare_test`，显式关闭真实模型。不得连接或重置旧 demo/真实账本。测量前拒绝已有活动任务，性能 fixture 按本次拥有的精确 ID 删除并验证所有原有业务行的计数及内容哈希恢复，不回退 sequence；历史 A/B/C/D1/D2 证据不覆盖。

## 日志契约

两类 Worker 的 `--log-json` 显式开启日志；默认关闭。原 CLI stdout 返回结果保持不变，结构化日志只写 stderr。不开启时不创建日志线程或 run_id，不增加数据库查询。

启用时，每次 `run_once` 分配一个独立 run_id。允许记录的业务关联字段只有 application_id、effect_key、shipment_request_id、outbox_id/task_id、owner、generation，以及真实存在的 Outbox attempt 或查询 cycle；shipment_request_id 不是 HTTP request ID。查询领取没有持久 attempt 字段，不以 generation 或虚构的零代替它。本批不宣称完成跨 HTTP/Agent/Inbox 的全链路 Trace。

记录领取、发送许可/查单许可、外部尝试、事务完成和整轮处理的开始、结束、耗时及结果。外部响应成功与领域提交成功分开：最终业务结果来自原 finish 返回的 request.status，失权必须记录失权，不能因 HTTP 成功就宣称出库完成。数据库事实和仓储记录才是完成证据。

字段采用白名单及有界标识符过滤；不记录 payload、正文、凭据、header、请求哈希或原始异常消息。非法或超过160字符的标识符省略。生产入口将已知仓储 token 提供给内存内过滤器，合法字符标识符中夹带该 token 也应丢弃。日志处理失败不改变原返回、异常、调用顺序或引发重试。

内置 sink 默认使用256条有界队列和非阻塞入队，独立 daemon writer 写入复制的 stderr 文件描述符。队列满时丢日志并累积计数；写失败熔断。正常退出调用 `close(timeout=0.25)` 有界等待收尾；业务线程不等待 stderr I/O，避免背压直接阻塞，但CPU/调度仍有开销，不承诺租约绝不过期。SIGKILL 可能丢失日志尾部；日志不作为提交凭证，也不保证无损传输。任意自定义阻塞 callback 不在内置 sink 的隔离保证内。

## 固定性能矩阵

每侧 2 类 Worker × 3 档进程数 × 3 轮 × 12 个请求，共 18 组、216 次正式处理。每组是新生成的合法申请和同一个目标 SKU，单件换货；通过原申请预览、确认、提交及履约服务推进到已批准出库。库存初始 20，完成后应为可用 8、预留 0、消费 12。

查单组预先通过真实 POST 制造“仓储已受理但返回丢失”的 UNKNOWN，再预建查询任务。该准备过程不计入正式 GET 吞吐；正式查询阶段不能再 POST 或改变仓储事实。性能 fixture 使用可信测试 Actor；真实员工认证及 HTTP 链路另由故障探针验证。

所有 Worker 完成启动后经共同门闩同时开始；记录启动耗时和门闩到最后一次成功 run_once 返回的时间，后者在事务提交后，作为批次吞吐分母。不能只用事务内赋值的 finished_at 当作已提交时刻。前后 ID 不同，只对照相同负载规格与不变量，不宣称整个响应字节相同。

保存门闩/创建到领取的排队时间、处理与外部尝试 p50/p95、SQL 游标次数/耗时、FOR UPDATE 次数及独立 PG 等待采样。Outbox 有持久 attempt.started_at；查询任务没有对应字段，只使用 run_once 入口作为代理，不能将其称为精确领取时间。

资源通过采样记录 Worker、HTTP 子进程和独立仓储的 RSS/累计 CPU，排除父测量进程和 PostgreSQL。RSS 可能重复计共享页并漏掉瞬时峰值；累计 CPU 包括启动且可能漏掉短命子进程，不能称为峰值 CPU 使用率。PG 采样未发现锁等待不代表没有短暂等待。监测开销在两侧均存在。

前后冻结同一测量脚本、依赖、机器、数据库版本、GUC、负载规格和原有业务行哈希；Worker 日志是本批预期源码差异。保留三轮原始值，不以少量本地样本宣称生产容量、SLA、线性扩容或日志零开销。未改善和回退指标必须列明。

## 并发和故障验收

纯服务集成测试覆盖 1／2／4 个领取者争抢同一请求、多个申请共享库存以及并发查询；真实进程探针另外覆盖：

1. 四个 Worker 同时争抢一个已批准请求，只形成一个仓储副作用。
2. CLAIMED/NOT_STARTED 后 SIGKILL，自然租约过期后由替代 Worker 完成。
3. 实际 HTTP 受理后、finish 前 SIGKILL，经查询恢复，不能再次 POST。
4. 旧未获发送许可的 Worker 暂停到失权，新 Worker 完成后旧执行不能再发送。
5. 旧 Worker 已获仓储受理结果后暂停，查单先完成，旧 finish 必须失权。

每个场景同时核对 provider 事实数/HTTP 记录、库存、申请状态和版本、reservation、原回执、triggered_by、owner/generation。真实进程必须有 PID、门闩/暂停点、杀进程和自然到期证据，不以重建对象代替杀进程。

## 停止点

首次失败原样保留，先定位再修复，不覆盖首次输出或换负载隐藏问题。任一重复出库、库存漂移、旧 Worker 新调用、权限回退或模糊结果误报成功均停止扩大矩阵。完成专项、完整离线回归、对照和交接后结束 D3，不自动启动 CI/Docker 或其他下一阶段。
