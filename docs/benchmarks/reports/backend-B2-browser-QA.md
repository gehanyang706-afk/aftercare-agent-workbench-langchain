## 10 月 28 日补验：实际 Chrome Headless 页面链路

用户要求继续后，使用本机已安装的 Chrome、捆绑 Node/Playwright，不使用 CUA、不下载浏览器。主代理在 `127.0.0.1:8132` 启动限时本地服务与新的临时员工账号；复用已保留的 bob 换货申请 `app_47739498e3974eab81b84a21bb2dbeac`，初始状态 `EXCHANGE_REQUESTED`、版本 1，没有清库或重置申请。

执行入口为 `runtime/backend-B2-ui-20261028/browser-driver.cjs`，凭据从同目录 0600 文件读取，不打印密码。driver 限定本地目的地，单步超时不超过 10 秒、全流程截止 145 秒；使用独立临时 Chrome profile 和客服、客户、仓库三个独立 BrowserContext，不触碰用户 profile。

**本次首次执行通过，耗时 5.272 秒。** 六个写入均由浏览器页面的表单和按钮完成；driver 只额外使用 GET 核对服务端结果，没有通过 API 请求绕过界面写入。

| 页面身份 | 实际界面动作 | 核对后的服务端状态 | 版本 |
|---|---|---|---:|
| 客服 | 员工登录、选择该申请、填写审核说明、点击“审核通过” | `AWAITING_RETURN` | 2 |
| 客户 bob | 客户演示入口登录、填写物流公司和寄回运单、点击“保存寄回信息” | `RETURN_IN_TRANSIT` | 3 |
| 仓库 | 员工登录、填写收货说明、点击“确认收货” | `RETURN_RECEIVED` | 4 |
| 仓库 | 点击“提交出库请求” | `REPLACEMENT_PENDING` | 5 |
| 仓库 | 点击明确标识的“本地模拟出库” | `REPLACEMENT_SHIPPED` | 6 |
| 客户 bob | 从原客户 context 刷新，点击“确认收到换货” | `COMPLETED` | 7 |

核对结果：

- 六次页面动作均显示预期状态，原操作离开对应可处理动作集合；完成态页面没有动作按钮。
- 原申请 `receipt` 与开始时逐值相同，`result` 仍为 `EXCHANGE_REQUESTED`；展开的“原申请提交凭据”仍显示“换货申请已提交”。
- 审计版本连续为 1—7，仅有一条 `confirm_shipment` 记录；模拟出库的 `triggered_by.actor_id` 与本次登录的仓库员工一致，并在时间线中可见。
- 页面明确显示“本地模拟出库”，出库单号以 `SIM-` 开头。此结果不代表连接真实物流，也不证明 C 的可靠外部投递。
- 三个页面没有捕获到 JavaScript `pageerror`。
